## Decisions that matter

- Select a category from the actual technology and verified delivery. A Flutter project compared with a Laravel competitor remains a Flutter project.
- Differentiate the buyer-visible **list price** from the author's **item-price entry**. For target list price `L` and verified category buyer fee `B`, enter `L − B`. Estimate proceeds from the current author-fee policy, not a remembered percentage. Keep the Extended price separate.
- Record confirmed category dimensions and formats before drawing the cover. Current cover requirements and legacy inline-preview fields may differ. Verify any thumbnail field rather than assuming a historic size applies everywhere.
- Include the required English offline documentation and check whether public online documentation is also required. For Flutter, cover app/package renaming, logo replacement, project structure and API configuration in addition to ordinary installation/use.
- Show actual application screens and disclose API, network, payment and hardware limitations. Availability of platform folders or a CI workflow is not a successful release build.
- Verify whether the category supports the ordinary paid support model before advertising a support duration.
- Account eligibility, product approval and publication remain separate facts. Record unavailable account evidence rather than treating an application-intake announcement as proof about an existing seller account.

## Price updates

Update target list price, author entry, estimated proceeds, metadata, index, pricing notes and any active checklist/research assumptions that repeat the selected price.
